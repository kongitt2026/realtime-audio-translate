# 翻译功能插件化封装方案 v1.0

> 对象：`offline_translate` 包（从「实时音视频翻译模块」中抽出的翻译内核）
> 目标：把翻译能力从视频翻译服务里解耦，变成**可独立安装、可嵌入任意 Python 项目、可命令行直接用**的插件
> 状态：**已实施并通过实测**（见第 7 节），不是纸面方案
> 建立：2026-11-09｜项目：实时音视频翻译模块（仓库根目录）

---

## 1. 为什么这样封（设计取舍）

| 取舍点 | 选择 | 理由 |
|---|---|---|
| 依赖范围 | 核心只依赖 `httpx` | 服务端才需要的 `fastapi/uvicorn/argostranslate` 全部做成可选 extras，装插件不必拖一个 Web 框架 |
| 翻译策略 | 引擎链（Google gtx → Google clients5 → Argos 离线） | 单点失败自动降级；gtx 高频会 429，实测常态走 clients5；断网走离线 |
| 扩展方式 | 继承 `Engine` 覆写 3 个方法 | 想接 DeepL/百度/自建模型，不用改核心代码，只加一个类 |
| 失败语义 | 返回 dict，不抛异常 | 字幕管道不能因为翻译失败中断；失败时 `translated` 回退原文并带 `failed/error` |
| 语言识别 | 内置 Unicode 区间法 | 零成本零网络；接第三方检测会让每次翻译多一跳延迟 |
| 与原服务关系 | `server/translator.py` 改为 shim 转发本包 | **单一实现**，避免服务内一份、插件一份两处漂移 |

## 2. 目录结构

```
实时音视频翻译模块/
├── offline_translate/            # ← 插件本体（可整包复制/独立发布）
│   ├── __init__.py               # 导出面 + 模块级单例 translate()
│   ├── __main__.py               # 支持 python -m offline_translate
│   ├── core.py                   # Translator 门面：识别→引擎链→缓存
│   ├── engines.py                # Engine 基类 / GoogleGTX / GoogleChrome / ArgosOffline / EngineChain
│   ├── lang.py                   # detect_lang / normalize_target / argos_code
│   └── cli.py                    # 命令行入口（xlate 命令）
├── pyproject.toml                # 打包元数据（name=offline-translate，version=1.0.0）
├── install_offline_models.py     # 可选：装 Argos 离线模型（ja_en / ko_en / en_zh）
└── server/
    ├── translator.py             # 兼容层：仅 sys.path + 转发导入（不再是实现）
    ├── main.py                   # HTTP 适配层：/api/translate、/api/engines
    └── pipeline.py               # ASR 管道（from translator import Translator 不变）
```

分层职责：`lang.py`（判语种，无依赖）→ `engines.py`（怎么翻，可插拔）→ `core.py`（编排：缓存/降级/返回结构）→ `cli.py` / `server/main.py`（对外形态，二选一或都用）。

## 3. 核心模块封装方式

### 3.1 引擎统一接口（`engines.py`）

```python
class Engine:
    name = "base"
    def available(self, src: str, target: str) -> bool:   # 能否处理这对语种
        return True
    def translate(self, text: str, src: str, target: str) -> str:  # 失败抛异常即换下一个
        raise NotImplementedError
```

内置三个实现：

| 类 | name | 说明 |
|---|---|---|
| `GoogleGTX` | `google` | `translate.googleapis.com/translate_a/single`，免费，高频 429 |
| `GoogleChrome` | `google_chrome` | `clients5.google.com/translate_a/t`，429 时的替补，实测中英日韩可用 |
| `ArgosOffline` | `argos` | 本地模型；无 ja→zh/ko→zh 直连，靠 `ja→en→zh` 两跳；`available()` 只放行 `target` 为 zh 的请求 |

`ArgosOffline` 的能力靠**探测**而非硬编码：`get_installed_languages()` 后取 `lang.get_translation(zh) is not None` 的语种集合；装完新模型调 `refresh()`（内部 `cache_clear()` + 重探测），无需重启进程。

### 3.2 编排层（`core.py` 的 `Translator`）

`translate(text, target=None) -> dict` 的处理顺序：

1. `strip()`；空文本 → `skipped=True`；
2. `detect_lang()` → `zh`/`other` 直接原样返回（不浪费一次网络请求）；
3. 查进程内 LRU-ish 缓存，key = `lang::target::text`（容量 `cache_cap`，默认 1000，`0` 关闭）；
4. 遍历引擎链：`available()` 为假 → 跳过；抛异常 → 记 `last_err` 换下一个；
5. 成功即写缓存并返回 `engine` 字段；
6. 全链失败 → `failed=True, error=...`，`translated` 回退原文。

线程安全：缓存读写和单例创建都过 `threading.Lock`（ASR 线程 + HTTP 请求线程并发调用已实测）。

## 4. 对外暴露的接口

### 4.1 Python API

```python
from offline_translate import translate, Translator

translate("今日は良い天気です。")
# {'original': '今日は良い天気です。', 'translated': '今天天气很好。',
#  'lang': 'ja', 'target': 'zh-CN', 'engine': 'google_chrome'}

tr = Translator(target="zh-CN", timeout=3.0, cache_cap=1000)
tr.translate("안녕하세요")                      # 单条
tr.translate_batch(["こんにちは", "안녕하세요"])   # 批量
tr.health()      # {'chain': [...], 'target': 'zh-CN', 'argos_ready': True,
                 #  'offline_langs': ['en','ja','ko'], 'cache_size': N}
tr.refresh_offline()   # 装完 Argos 模型后热更新，不重启
tr.close()             # 释放 httpx 连接
```

返回字段全表：

| 字段 | 出现时机 | 含义 |
|---|---|---|
| `original` / `translated` | 总是 | 原文 / 译文 |
| `lang` | 总是 | 识别语种 `zh/ja/ko/en/other` |
| `target` | 总是 | 归一后的目标语种 |
| `engine` | 实际翻译成功 | 生效引擎名 |
| `cached` | 命中缓存 | 无 `engine` 字段 |
| `skipped` | 中文/无法识别/空串 | 原样返回，未消耗网络 |
| `failed` + `error` | 全链失败 | 译文回退原文 |

自定义引擎示例（接自有模型/付费 API）：

```python
from offline_translate import Translator, Engine

class MyModel(Engine):
    name = "my_model"
    def available(self, src, target): return target.startswith("zh")
    def translate(self, text, src, target): return my_api(text, src, target)

tr = Translator(engines=[MyModel(), *Translator._default_engines(3.0)])
```

### 4.2 命令行（CLI）

```powershell
python -m offline_translate "今日は良い天気です。"
python -m offline_translate "오늘은 날씨가 정말 좋습니다." --json
python -m offline_translate --check                 # 引擎链 + 离线语种 + 缓存条数
echo "こんにちは" | python -m offline_translate -
python -m offline_translate --file in.txt -t en
python -m offline_translate "text" --engine argos   # 只用离线（验证兜底）
```

装包后可直接用 `xlate`（pyproject 里的 `[project.scripts]`）：`xlate "안녕하세요"`。
退出码：`0` 成功 / `1` 翻译失败 / `2` 未知引擎。

### 4.3 HTTP 接口（复用本项目服务时）

| 方法 | 路径 | 入参 | 返回 |
|---|---|---|---|
| POST | `/api/translate` | `{"text": "..."}` | `{"ok": true, original, translated, lang, target, engine}`；空文本 400 |
| GET | `/api/engines` | — | `{"chain": [...], "target", "argos_ready", "offline_langs", "cache_size"}` |
| POST | `/api/play` | `{"url": "..."}` | 起拉流翻译，字幕走 `WS /ws` |

响应头为 `application/json; charset=utf-8`（`Utf8JSONResponse`）。**不声明 charset 时 PowerShell 5 `Invoke-WebRequest` 会按 Latin-1 解码显示乱码**，这是本轮实际踩到并修掉的坑。

请求侧同理：PS 5 的 `-Body '{"text":"韩语…"}'` 默认按 ASCII 编码，中文/日韩文会变成 `???`（实测服务收到 `lang=other`、直接 skipped，看起来像"翻译失效"）。正确写法是显式传 UTF-8 字节：

```powershell
$body = [System.Text.Encoding]::UTF8.GetBytes('{"text":"회의는 오후 3시에 시작합니다."}')
Invoke-WebRequest -Uri http://127.0.0.1:8790/api/translate -Method POST `
  -Body $body -ContentType "application/json; charset=utf-8" -UseBasicParsing
# → {"ok":true,"original":"회의는 오후 3시에 시작합니다.","translated":"会议于下午 3 点开始。","lang":"ko",...}
```

## 5. 安装与使用步骤

### 5.1 在本项目内使用（零安装）

项目根已在 `sys.path`（`server/translator.py` 负责注入），直接 `from offline_translate import translate` 即可。

### 5.2 作为可安装包

```powershell
cd <本项目根目录>

# 仅在线翻译（只要 httpx）
.venv\Scripts\pip.exe install -e .

# + 离线兜底（断网/限流可用）
.venv\Scripts\pip.exe install -e ".[offline]"
.venv\Scripts\python.exe install_offline_models.py

# 验证
.venv\Scripts\python.exe -m offline_translate --check
.venv\Scripts\xlate.exe "今日は良い天気です。"
```

### 5.3 复制到别的项目

```
复制 offline_translate/ 到目标项目根 → 目标项目 pip install httpx
（需要离线）pip install argostranslate + 运行 install_offline_models.py
```

不打轮子也能用；要分发给他人再 `python -m build` 出 sdist/wheel。

### 5.4 起服务并验证

```powershell
.\启动.bat            # 或 .venv\Scripts\python.exe server\main.py
.venv\Scripts\python.exe tests\test_translate_ja_ko.py    # 16 项端到端
```

## 6. 兼容性配置说明

| 项 | 约束/默认 | 说明 |
|---|---|---|
| Python | ≥3.9（本项目 3.13 实测） | 代码用了 `dict[str, str]` 等 3.9 语法与 `from __future__ import annotations` |
| 核心依赖 | `httpx>=0.24` | 唯一硬依赖；可注入自定义 `httpx.Client`（走代理/改超时） |
| 离线 extras | `argostranslate>=1.9` | 不装则 `argos` 引擎 `available=False`，自动跳过，不报错 |
| 服务 extras | `fastapi>=0.110`, `uvicorn>=0.27` | 仅复用 `server/main.py` 时需要 |
| 网络 | 需能访问 `translate.googleapis.com` / `clients5.google.com` | 被墙/限流时自动落到 `argos`；代理可传 `client=httpx.Client(proxy=...)` |
| 目标语种 | 默认 `zh-CN`；别名 `zh/zh-cn/zh-hans→zh-CN`、`zh-tw`、`en/ja/ko` | 别名归一见 `lang.normalize_target`；Argos 只用两位码 |
| 超时 | 默认 3.0s（每个 HTTP 引擎） | 实时字幕场景不宜再大；批处理可调 10s |
| 缓存 | 默认 1000 条，`cache_cap=0` 关闭 | 只存成功结果；超出弹最早插入的 key |
| 离线模型 | ja_en / ko_en / en_zh，落 `~/.local/share/argos-translate/packages` | 装完必须 `refresh()` 或重启进程（`get_installed_languages()` 有 lru_cache） |
| 语种识别 | 假名>谚文>汉字>拉丁 | **纯汉字日语句会被判成 zh 而跳过翻译**，已知取舍；需要更准时换成 fastText/CLD3 |
| 编码 | 输入输出均 UTF-8；HTTP 显式 `charset=utf-8` | Windows 控制台需 `$env:PYTHONIOENCODING="utf-8"`，否则中文输出可能 `UnicodeEncodeError` |
| 并发 | 线程安全 | 引擎内部 httpx.Client 线程安全；缓存加锁 |
